## What happened today (incident post-mortem)

### Root causes

1. **Spotify took 3 hours** — `llm_verify_artist_match()` used a 60s timeout per
   `claude -p` call, and ran on many artists. Spotify + email both launched in parallel
   but system scheduling caused email to land late (~11:44 TPE, not ~09:15).
2. **No notified markers** — `send_email.py` didn't write `data/notified/email-{date}`.
   GH Actions saw `email_done=false`, re-sent at 12:24 TPE (duplicate).
3. **npm install in GH Actions** fired even when only email was needed (pure Python,
   no npm). npm failed on network flakiness → whole run flagged as `failure`.

### Fixes shipped

| Fix | File |
|---|---|
| LLM verify timeout 60s → 15s | `scripts/update_spotify.py` |
| `update_spotify.py` writes `data/notified/spotify-{date}` on success | `scripts/update_spotify.py` |
| `update_spotify.py` exits 1 when credentials missing | `scripts/update_spotify.py` |
| `send_email.py` writes `data/notified/email-{date}` on success | `scripts/send_email.py` |
| `send_email.py` exits 1 on non-200 Resend response | `scripts/send_email.py` |
| `run_daily_dig.sh` captures SPOTIFY_EXIT / EMAIL_EXIT, logs `[ERROR]` on failure | `scripts/run_daily_dig.sh` |
| `run_daily_dig.sh` commits `data/notified/` after both scripts complete | `scripts/run_daily_dig.sh` |
| GH Actions: single `already_done` gate → independent `pipeline_done/spotify_done/email_done` | `.github/workflows/daily-dig.yml` |
| GH Actions: npm install only runs when pipeline step needs it | `.github/workflows/daily-dig.yml` |
| GH Actions: failure issue now names which specific step failed | `.github/workflows/daily-dig.yml` |
| GH Actions: `Commit notified markers` step added | `.github/workflows/daily-dig.yml` |
| Both scripts: `--force` flag bypasses marker guard without deletion | `scripts/send_email.py`, `scripts/update_spotify.py` |
| Both scripts: refuse to run if marker exists (unless `--force`) | `scripts/send_email.py`, `scripts/update_spotify.py` |

**Post-session triple-send (root cause):** Deleted `email-2026-05-06` marker mid-session
to allow a manual resend, then never re-added it. The scheduled cron (GitHub delayed it
2.5 hours to 14:33 TPE) saw `email_done=false` and fired a third send. Fix: scripts now
refuse to run if marker exists. Resending requires `--force` — no marker deletion ever needed.

**Correct resend procedure going forward:**
```bash
python3 scripts/send_email.py --date 2026-05-06 --force
# or via GH Actions (uses secrets):
gh workflow run daily-dig.yml --repo <owner>/<repo>
```

## Other work this session

### Archive: pick count

Archive page (`/archive/`) now shows number of picks (albums) per digest instead of
number of sources. Counts `## ` headings in the digest markdown body — matches exactly
what the email subject line reports (`len(records)` from parsed JSON).

### Site: Spotify footer link

Footer redesigned to two-column flex layout on both index and digest pages:
- Left: Sources list
- Right: Full Archive · Listen on Spotify

Files: `site/src/pages/index.astro`, `site/src/pages/digest/[...date].astro`,
`site/src/styles/newspaper.css`

Playlist: https://open.spotify.com/playlist/0x4VHy7xmcxRx5LVb9pGRU

### Spotify: LLM artist verification

Added `llm_verify_artist_match()` in `update_spotify.py`. When album search fails and
we fall back to artist top-track search, the LLM confirms the returned track's credited
artists match the artist we searched for. Prevents wrong-artist tracks (e.g. "The Dowser"
matching for "Dowser" — different artist).

Also updated `get_artist_top_track()` to fetch 10 tracks and filter to only those where
the searched artist is the primary (first) credited artist.

### Cover art: dual media format support

Facebook posts use two different field names for image URIs:
- Instagram-style: `media[].image.uri`
- Facebook-native: `media[].photo_image.uri`

Updated `parsing.md` to check both. Backfilled 6 missing covers for 2026-05-06.

### Hero scoring: proportional descriptions

Previous: "1-3 sentences" for all descriptions → parser truncated rich posts.
Now: "typically 2-3 sentences, up to 4-5 for rich posts" — matches the actual
post content depth. Hero scoring in `score-hero.ts` uses `description_en.length +
descriptionZh.length * 0.3`, so richer descriptions score higher and better albums
win the hero slot.

## Routines research notes (for reference)

Investigated Claude Code Routines as alternative scheduler. Decision: **stick with
launchd + GH Actions backup**.

- **Local Routines** (desktop app): require Mac awake + desktop app open — strictly
  more constrained than launchd. No benefit.
- **Cloud Routines**: run on Anthropic infrastructure, Mac can be off. BUT no secrets
  management for env vars (APIFY_TOKEN etc.), daily execution quota (5/15/25 per plan
  tier), research preview status. Not suitable for this pipeline.
- The launchd + GH Actions stack covers all failure modes that matter.

## Gotchas / things to know

### SQLite Phase 2 — DB-first, JSON fallback

`dedup_raw.py` and `dedup_albums.py` query SQLite first. If `data/dig.db` doesn't
exist (hypothetical fresh checkout without the committed DB), they fall back to JSON.
The DB is committed so this shouldn't happen, but the fallback is there.

The `UNIQUE(post_url, artist_norm, album_norm)` constraint on `albums` will now raise
on parser image-collision bugs at insert time — that's intentional (loud canary).

### Parser image-collision bug class

The Claude parser sometimes copies one record's `post_url` and/or `image_url` onto a
neighboring record. Three instances on 2026-05-04. Root-cause fix is Phase 3 (SHA-256
collision query on `covers` table). Until then, check `data/raw/{date}-apify.json`
(gitignored but present locally) for the correct media URLs.

### Cover filenames are now content-hashed

Covers saved as `{slug}-{hash8}.jpg`. `site/public/_headers` sets `Cache-Control: immutable`
for `/covers/*`. If a cover ever changes, new hash = new filename = automatic cache bust.
`migrate_covers_to_hash.py` ran on 2026-05-05 (43 files renamed).

### pfbid URL rotation (mitigated)

Facebook pfbid URLs are unstable — the same post can appear with a different pfbid on
consecutive scrape days. This caused URL-based dedup (`dedup_raw.py`) to treat it as
a new post, and since parser artist spelling may vary between scrapes, the
`(artist_norm, album_norm)` key in `dedup_albums.py` sometimes also missed it.

Two mitigations now in place (commit `732e11f`):
- **Option A** (`dedup_albums.py`): same `source_page` + `album_norm` → duplicate,
  regardless of artist spelling variation.
- **Option B** (`dedup_covers.py`): post-fetch SHA-256 cover hash comparison against
  the 14-day window. Identical image bytes = same release.

Real example caught: "Nuclear War" by The Heliocentrics appeared on both 2026-05-04
and 2026-05-05 from `beethobearrecords` with different pfbids and slightly different
artist name. Both layers would now block the 05-05 entry.

### Cloudflare Pages preview URLs are frozen forever

Each deploy creates a permanent preview URL. Production alias (`music.erdscribe.com`)
tracks the latest. Don't use preview URLs for verification.
